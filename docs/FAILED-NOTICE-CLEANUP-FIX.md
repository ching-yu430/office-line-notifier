# 失敗通知與紀錄清理修正：2026.11.19.2

本修正以 2026.11.19.1 為基礎，保留三個系統管理分類與暖黃色版面。只修改程式與文件，沒有部署正式網站、刪除正式資料、重送 LINE 或變更憑證。

## 原因與修正

首頁原本只看發送結果為 failed／uncertain，即使已標記處理完成仍會持續顯示「發送需檢查」。現在首頁與通知紀錄的「需要檢查」均排除已完成項目，原發送失敗原因仍保留於歷史查詢。失敗的包裹通知若標記處理完成，顯示「已處理」，避免誤顯示已領取。

原清理只接受指定日期零時以前的已完成紀錄，預設是一年前。近期資料不符合日期條件；未送出的失敗通知也常保留待回覆／待領取狀態，因此不會出現在舊清理範圍。現在加入「全部日期（含今日）」及獨立的「發送失敗通知」，沒有把所有歷史自動改成可刪除。

## 已上傳 2026.11.19.1 時如何更新

1. 下載 **office-line-notifier-failed-cleanup-fix.zip** 並解壓。
2. 將包內 **src、worker、tests、docs 四個資料夾**合併至電腦上的原完整專案，覆寫同名檔案並保留其餘舊檔。不要刪除原資料夾。
3. 在原完整專案根目錄執行：

```powershell
fnm env --shell powershell | Out-String | Invoke-Expression
fnm use 24
npm.cmd ci
npm.cmd test
npm.cmd run build:cloudflare
```

4. 確認結果成功後，到 `npust-lc/office-line-notifier` 的 main 根目錄，Add file → Upload files，從修正包解壓資料夾拖入上述四個資料夾並提交。main 提交會觸發既有 Pages 正式部署。
5. Pages 部署成功後，開正式網站按 Ctrl＋Shift＋R。系統管理 → 一般設定，介面及後端版本應同為 **2026.11.19.2**。

本修正沒有新增 Migration、套件或 Secrets。已完成上一版 0003／0004／0005 者，不需要再執行資料庫升級，也不需要重設帳密或 LINE Token。原環境檔與 wrangler 設定沿用。

修正包只包含本次差異，不能單獨當作完整專案。若先前尚未上傳累積修改，請使用另附的 **office-line-notifier-combined-update.zip**，依 [整合更新說明](CONVERSATION-UPDATE.md) 合併六個資料夾與四個根目錄檔案，確認尚未執行的 Migration。

## 清理之前的兩筆 401 紀錄

更新成功後由管理員操作：

1. 在系統管理 → 資料維護 → 紀錄備份，先下載一份紀錄 ZIP 並確認保存。
2. 到旁邊的紀錄清理，日期範圍選 **全部日期（含今日）**。
3. 只勾選 **發送失敗通知**；取消已完成通知與聊天、已完成交接、舊操作紀錄。
4. 按「預覽可清理紀錄」。若只有原本兩筆符合條件，應顯示通知 **2 筆**，聊天／交接／操作紀錄都是 **0**。若筆數不符合預期，可取消預覽後核對通知歷史。
5. 確認已備份及筆數正確，輸入 **刪除紀錄**，按「確認永久刪除」。
6. 完成後首頁重新計算提醒，操作紀錄會保留清理人員、時間與失敗筆數。這個流程不會重新發送通知，也不會修改 LINE 憑證。

若只想結束追蹤而保留原通知，可在通知紀錄將其處理狀態改成已處理；修正版首頁便不再計入這筆提醒。

## 保留條件及空白結果

- 指定日期以前仍採台灣時間，且不包含所選當日；要清理近期已完成紀錄請選全部日期。
- 發送失敗通知必須為 failed、沒有送出時間、沒有聊天引用，且不在快速復原期間。此範圍可以清理其待處理紀錄，需明確勾選並確認。
- 待發送、傳送中、結果未明、已送出的未完成待辦、未完成交接、每位教師最後一則聊天及仍可快速復原的紀錄均保留。
- 聊天只清理已完成對話的舊訊息；教師還有待處理通知時仍保留。已完成通知若被保留的聊天引用，也會保留。因此全部日期不表示可以清空所有資料。
- 已完成交接剛標記完成時，有 60 秒快速復原保護；保護期結束後才符合清理條件。
- 發送失敗和一般通知合計每批最多 100 筆；其餘分批限制沿用。預覽後只處理原目標，不包含後來新增的紀錄。
- 目標版本、發送結果、聊天引用或處理狀態變更會整批拒絕；SQL 失敗整批回滾。已清理的發送請求仍保留封存識別，拒絕舊頁面重送。

## HTML 預覽

解壓 **office-line-notifier-html-preview.zip**，用 Chrome 開啟其中的 HTML。系統管理 → 資料維護 → 紀錄清理 → 測試工具，按「加入失敗通知範例」，會建立兩筆虛構 401 紀錄。可先返回首頁查看提醒，再依上方步驟選全部日期、只勾失敗通知，預覽並清理。所有內容均為虛構，沒有正式 API 或 LINE 請求；正式網站沒有這個測試工具。
