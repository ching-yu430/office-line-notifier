# 介面與操作修整：2026.11.17.2

本版延續既有暖黃色、紙白、暖褐配色與原始透明 Logo，保留六張卡片同排、系統管理左右配置、教師綁定、共同值班與文字通知流程。

## 調整內容

- 總覽縮短卡片高度，加入當日已送出、已領取、交接完成進度；待回覆依最近聯絡排序，發送異常可直接進紀錄核對。
- 批次通知只全選目前搜尋結果；已選教師列成可移除標籤。每批最多 100 位，未綁定不能選；發送前若有人停用或解除綁定，介面會要求移除。
- 通知紀錄直接查詢 D1 的全部歷史紀錄，不受最近 500 筆限制；增加今日／近一週／指定期間與清除篩選，每頁 10 筆，表格區固定高度捲動。日期採台灣時間，已送出依送出時間、未送出依建立時間篩選。
- 可開啟完整通知內容，查看對象、類型、經辦與處理狀態，再直接進入對話。發送時間顯示實際送出時間，尚未發送不顯示成已送出。
- 教師名單顯示實際符合的筆數，搜尋不受前後空白與英文大小寫影響；停用狀態明確顯示，長名單在固定區域捲動。
- 聊天按日期分段，回覆可換行；Enter 換行、Ctrl＋Enter 或點按送出。中文輸入法組字時不會因確認文字而送出。
- 閱讀舊訊息時保留捲動位置；新訊息顯示「查看最新」，回到最新後才更新內部未查看狀態。這與 LINE 已讀不同，未加入 LINE 標記已讀 API。
- 聊天高度配合電腦視窗調整，較矮的視窗也盡量保持回覆框可見。手機選擇教師後直接進對話，按返回箭頭回名單；切換教師保留當次登入期間的草稿。
- 成功提示移至較不遮擋操作的位置，可按叉號關閉。領取、交接原本的快速復原與完整操作紀錄保留。
- 登入頁增加顯示／隱藏密碼。預覽網址會提示正式入口並停用該頁登入，減少「來源不允許」的困惑。
- 系統管理可核對介面與後端版本，判斷是否部署或快取未同步。

沒有新增稍後追蹤、常用回覆管理、附件上傳、Supabase 或 R2。本版仍只處理 LINE 文字；文件及附件由辦公室 Email 處理。

## 本次更新方式

你已套用 `0002_workflow.sql`，本版**不需要再執行任何資料庫遷移**，不需重設帳號、密碼、教師綁定、LINE Token 或 Secrets。

1. 解壓縮更新包，將 `src`、`worker`、`tests`、`docs` **四個資料夾**合併到原完整專案根目錄（有 `package.json` 的那層），覆寫同名檔案，其餘原檔保留。不要只複製 `main.tsx`，它有新的元件與樣式相依。
2. 本機先預覽。準備更新正式網站時，在 GitHub `npust-lc/office-line-notifier` 根目錄選 **Add file → Upload files**，拖入更新包內的四個資料夾；路徑須直接是 `src/...`、`worker/...`、`tests/...`、`docs/...`。
3. 提交 `main` 會觸發現有 Cloudflare Pages 部署，這一步會更新正式網站。原有 `wrangler.jsonc`、D1 ID、正式網址、Secrets 保留。
4. 等 Pages 的最新 **Production／正式部署**成功後，開啟固定網址 `https://office-line-notifier.pages.dev/`，按 `Ctrl + Shift + R`。不要把部署清單的亂數預覽網址當作正式入口。
5. 管理員在「系統管理」檢查介面及後端版本，應為 `2026.11.17.2`。若只看到介面版本或後端仍是前一版，請確認 `worker` 與 `src` 同次更新，並確認部署成功。

更新包不含設定檔、環境變數、Secrets、備份、真實帳密或教師個資；也不含本機 `node_modules`。本版假設原專案已有 0001、0002 與前次更新，不能只靠此更新包從空資料夾啟動。

## Windows PowerShell 本機預覽

在原專案資料夾執行，若新視窗找不到 Node，先初始化原本的 fnm：

```powershell
fnm env --shell powershell | Out-String | Invoke-Expression
fnm use 24
npm.cmd ci
```

只在自己的電腦預覽虛構資料，不啟動 LINE 後端：

```powershell
$env:VITE_APP_MODE = "mock"
$env:VITE_BASE_PATH = "/"
npm.cmd run dev -- --host 127.0.0.1
```

開啟終端顯示的本機網址，通常是 `http://127.0.0.1:5173/`。停止展示按 `Ctrl + C`。展示不會發送 LINE，也不會修改正式 D1。

結束後可清除本次 PowerShell 的展示選項：

```powershell
Remove-Item Env:VITE_APP_MODE -ErrorAction SilentlyContinue
Remove-Item Env:VITE_BASE_PATH -ErrorAction SilentlyContinue
```

驗證指令（不會部署）：

```powershell
npm.cmd test
npm.cmd run build:cloudflare
```

## 登入網址與安全

新增 `GET /api/public-info`，僅回傳系統名稱、設定的正式網址及版本，不含帳號、Token、密碼、Session 或教師資料。登入頁可從同一網站讀取此資訊，提供正式入口；帳密登入、管理資料、CSRF 與來源檢查仍維持原有保護，沒有開放預覽網址操作正式資料。

若後端尚未更新而沒有此 API，介面會沿用原登入流程，不會因讀取版本資訊而清除登入狀態。密碼只在輸入及登入請求期間使用，沒有新增瀏覽器持久保存。

歷史查詢使用受 Session、Origin 與 CSRF 保護的 `POST /api/notifications/query`；搜尋文字放在 JSON 本文，不放在網址。查詢值皆以 SQL 參數綁定，結果不包含 LINE User ID、重試鍵或操作識別 Token。

## 驗收與限制

以自己的測試教師操作：搜尋選人、預覽批次通知、多行回覆、閱讀舊訊息後收到新訊息、領件與復原、日期篩選、通知完整內容、手機返回名單。正式 LINE 收發驗收仍需由使用者確認後操作，開發測試使用 Mock。

正式通知紀錄由後端查詢全部 D1 通知，計算總數並每次返回 10 筆；展示版使用本機虛構紀錄。可按「重新載入」核對其他人對較早紀錄的修改。搜尋採 200 毫秒防連續查詢，每人每分鐘最多 90 次；需要時縮小教師、日期或處理狀態範圍。個別教師對話另載入最近 200 則訊息及最多 200 筆待領件。草稿與未明發送請求只在當次登入期間的記憶體保留，重新整理或登出後須先核對發送紀錄，避免重複送出。
