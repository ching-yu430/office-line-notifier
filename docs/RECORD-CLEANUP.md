# 紀錄清理（沿用於 2026.11.19.1）

管理員在「系統管理」的「資料維護」分類直接操作「紀錄清理」，用來減少長年累積的文字與紀錄。維持既有暖黃色版面，沒有新增附件、儲存服務、排程刪除或付費套件。本次只建立程式與測試，沒有清理正式資料庫。

## 操作方式

1. 以管理員登入，進入「系統管理 → 資料維護 → 紀錄清理」。一般行政人員沒有此權限，後端也會拒絕請求。
2. 日期預設為一年前，可依辦公室保存規範調整；清理的是台灣時間該日零時以前，**不含當日**。
3. 選擇範圍：「已完成通知與聊天」、「已完成交接」、「舊操作紀錄」。舊操作紀錄預設不勾選。
4. 按「預覽可清理紀錄」，先查看各類筆數。此步驟不會刪除歷史。
5. 確認已備份，輸入完整的「刪除紀錄」，再按「確認永久刪除」。可以取消；刪除後不能使用領件的快速復原。
6. 完成後顯示實際清理筆數，並在最近操作紀錄留下清理人員、時間、日期界線與筆數。若本批達上限，可再預覽下一批。

預覽十分鐘有效，只能由原管理員執行。相關通知版本、交接狀態或聊天待處理狀態若變更，整批拒絕刪除並要求重新預覽，不會部分清理。新進入清理條件的其他紀錄不會被順帶刪掉。網路中斷時可重試同一預覽，後端只會執行一次。

## 哪些資料會保留

| 類別 | 清理規則 |
| --- | --- |
| 通知 | 建立及完成時間均早於所選日期，狀態為已完成，且發送已結束。仍被保留訊息引用的通知不刪除。待領取、待回覆、待發送、傳送中與結果未明保留。 |
| 聊天 | 只清理已完成對話的較早訊息；該教師若有未完成通知、發送未明或仍可快速復原的領件，保留相關聊天。每位教師最後一則訊息一定保留。 |
| 交接 | 建立及完成時間都早於所選日期，且沒有仍有效的快速復原。一併刪除該筆交接的修改歷程；尚在待處理的交接不刪。 |
| 操作紀錄 | 只有明確勾選此類才會清理較早的操作紀錄；**歷次清理摘要永遠保留**。 |
| 其他 | 教師名單、LINE 綁定、綁定碼、帳號、範本、內部備註與目前處理狀態不刪除。 |

若僅清理交接而未勾選舊操作紀錄，交接相關的一般操作紀錄會保留，解除對已刪除交接的外鍵參照；完整的交接內容及修改歷程會刪除。

每批最多 **300 則聊天、100 筆通知、50 筆交接及 300 筆操作紀錄**，降低一次刪除過多資料的負擔。交接修改歷程隨該批交接一併處理，會先列出筆數。日期預覽每位管理員每分鐘最多十二次。

索引與觸發器也會消耗 D1 讀寫額度，大量歷史資料請分批清理並查看 Cloudflare Metrics，必要時分日處理；分批上限不代表每日可無限次執行。

系統會保留精簡的 Webhook 事件識別、撤回識別與發送請求帳本，避免 LINE 重送或舊瀏覽器重試時重新出現訊息或再次通知老師。已清理通知的發送請求會標記封存，不能再沿用原請求發送。這些識別資料不是附件或聊天正文。

## 容量的實際影響

刪除能減少保留的文字與有效資料列，讓 SQLite／D1 重用空間。資料庫顯示的配置容量及既有備份大小**不一定立即縮小**，不應用按下清理後容量立刻下降作為成功標準；以清理結果、資料查詢及後續用量為準。系統不會自動執行 VACUUM、重建正式資料庫或刪除外部備份。

預設保留最近一年只是操作起點，實際保存年限由辦公室決定。清理過的內容不會再出現在搜尋或歷史紀錄，舊備份仍可能保留已刪除資料。

## 先在 HTML 試用

解壓 HTML 預覽包，用 Chrome 開啟 `office-line-notifier-preview.html`。到系統管理「資料維護」分類的紀錄清理，展開「測試工具」，按「加入舊紀錄範例」。可直接試用日期預覽、取消與確認刪除，所有資料都是虛構，不會連線正式 D1 或發送 LINE。正式網站沒有此測試工具。

## 確認更新正式網站後才執行

先依 [整合更新說明](CONVERSATION-UPDATE.md) 合併六個資料夾與四個根目錄檔案，保留原 `wrangler.jsonc`、環境檔及 Secrets。在原完整專案根目錄執行：

```powershell
fnm env --shell powershell | Out-String | Invoke-Expression
fnm use 24
npm.cmd ci
npx.cmd wrangler d1 migrations list office-line-notifier --remote
New-Item -ItemType Directory -Force .local | Out-Null
$officeBackupPath = Join-Path ".local" ("before-0005-" + (Get-Date -Format "yyyyMMdd-HHmmss") + ".sql")
npx.cmd wrangler d1 export office-line-notifier --remote --output $officeBackupPath
npx.cmd wrangler d1 migrations apply office-line-notifier --remote
npx.cmd wrangler d1 migrations list office-line-notifier --remote
```

目前整合版會依序套用尚未執行的 0003、**0004_record_cleanup.sql**、0005；已執行的遷移不會重跑。0004 只新增清理帳本、稽核摘要欄位、索引及發送請求封存欄位，不會自動刪除任何歷史資料。

確認備份成功、沒有待套用遷移後，才由網站擁有者確認上傳 GitHub main 觸發正式部署。正式版介面／後端版本應同為 `2026.11.19.1`。目前整合版另需套用 0005（備份版本）；不要先部署新程式卻漏套用所需遷移。

每次真正清理前，可同樣執行備份指令，將檔名前綴改成 `before-record-cleanup-`。備份含敏感資料，只留在學校核准的位置，不要上傳 GitHub 或放進公開更新包。還原應先在另一個資料庫演練，依 [維運文件](OPERATIONS.md) 核對 Migration、帳號及綁定，再安排切換。

## 實作與測試範圍

`records_cleanup_preview` 只儲存短期的目標識別及數量；`records_cleanup_execute` 以 Session、Origin、CSRF、後端角色及預覽擁有者驗證。目標重新檢查、發送帳本封存、關聯資料刪除與清理稽核在同一 D1 原子批次提交。任一步 SQL 失敗會整批回滾。完成後清除預覽目標清單，只保留精簡的執行識別及結果，防止重複執行。

每位教師保留最後訊息也保留了 SQLite 入站序號的最高水位，避免清空訊息後 rowid 重用導致「未查看」判斷錯誤。Webhook 去重、撤回識別與發送防重複資料不隨正文一起清理。

新增自動化涵蓋權限、日期界線、取消與確認、逾時、不同操作人、預覽後新訊息／交接變更、同時執行、SQL 失敗回滾、分批、Webhook 重送、清理後未查看序號與舊發送請求拒絕重送，以及 0004 升級保留既有資料。實際測試結果見 [TEST-REPORT.md](TEST-REPORT.md)。所有 LINE HTTP 都為 Mock，未執行真實 LINE 或正式資料清理。
